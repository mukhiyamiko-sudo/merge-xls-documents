# 合并文档 V5｜最终产品需求与技术验收基线

状态：最终功能版本。本文档是复现 V5 的唯一现行需求基线。V1—V4 只是开发过程中持续修复问题、完善交互的迭代记录，不是四套需要分别实现或交付的产品；接手者只须实现本文件定义的 V5 最终效果。项目内早期的《需求文档》仅供追溯历史，不得覆盖本文件。日期：2026-10-10。

## 1. 目的与交付物

用户经常收到上百份同类型的旧版 `.xls` 索赔明细。程序把指定文件夹第一层的全部合格文件，或用户直接拖入的一组同文件夹文件，按文件名顺序合并为一份新工作簿：Windows 输出 `.xls`，macOS 输出 `.xlsx`。它必须删除每份源表底部的五项汇总，并在最左侧增加从源文件名提取的 `Invoice number`。用户先看到识别数量，确认后亲自点击“开始合并”；扫描或拖入本身不能触发合并。

交付形态：Windows 为双击运行、无命令行窗口的 EXE；macOS 为双击运行的 `.app`。两个平台的业务结果及交互规则相同。macOS 指定验收设备是 Intel MacBook Pro（Late 2013），macOS Big Sur 11.7.9，16 GB 内存。macOS 包必须在这台或同配置的 Big Sur Intel Mac 上做最终运行验收；在更新版 macOS 上成功打包不能替代该验收。

非目标：不支持把 `.xlsx` 当作源文件、递归扫描子文件夹、跨文件夹拖入文件、自动开始合并、覆盖源文件、云端处理或突破既定的 65,536 行上限。不要重做项目架构或改变已经确认的合并结果。

## 2. 输入与发现规则

### 2.1 两种载入方式

1. 拖入**一个文件夹**：只扫描其第一层，不进入子文件夹。
2. 拖入**一个或多个文件**：只取拖入的 `.xls`，所有可处理文件必须处于同一父文件夹；没有被拖入的同目录文件不得偷偷加入本次清单。混入的非 `.xls` 或 Excel 临时文件可忽略，并在日志中说明忽略数量。
3. 点击“选择文件夹”按钮或拖拽区的空白位置：打开系统文件夹选择器，按方式 1 载入。

源文件扩展名 `.xls` 大小写不敏感。排除以 `~$` 开头的临时文件。旧结果文件名匹配 `合并结果_YYYYMMDD_HHMMSS.xls` 或 `.xlsx`，也可能带 `_2`、`_3` 等序号；它们永不进入源清单。如果发现旧结果，扫描日志告知数量；用户点击“开始合并”时先弹窗确认，拒绝则不处理，确认后仍排除旧结果。若直接拖入的文件来自不同父目录、混入文件夹，或没有 `.xls` 源文件，显示明确警告，不合并。

候选源文件按**文件名不区分大小写从小到大**排序；同一规则用于预扫描清单和最终处理。预扫描只按文件位置、名称和扩展名发现候选文件、显示数量，**不在此阶段读取或校验表内数据**；表头、底部汇总和 Invoice number 的校验仅在点击“开始合并”后进行。若清单为空，开始按钮禁用并在日志说明原因。

### 2.2 可识别的文件内容

`.xls` 有两种实际格式，均须支持：

- Excel 97–2003 二进制工作簿。只读第一个工作表。
- 扩展名仍为 `.xls` 的 HTML 表格文件。能够从外层嵌套表格中找到符合要求的明细表；HTML 实体（包括 `&nbsp;`）及普通空白按可见文字解析。

扩展名正确但内容不是上述格式，属于该文件的异常，跳过并记录原因。读取不依赖 Microsoft Excel 或 Apple Numbers 的安装。

## 3. 源表结构与校验

源明细必须固定为以下十列，顺序不能变。比较表头时忽略大小写及多余空白，普通空格和不换行空格等同；列名和顺序仍须一致。

| 列 | 源表表头 |
|---:|---|
| 1 | CODE |
| 2 | DESCRIPTION |
| 3 | ITEM # |
| 4 | ITEM DESCRIPTION |
| 5 | UPC |
| 6 | MODEL # |
| 7 | UNIT COST |
| 8 | CLAIM QTY |
| 9 | UOM |
| 10 | CLAIM AMT |

任一表头不一致、明细行不是十列、或第十列后存在非空数据，跳过整个文件。HTML 表格可以有用于排版的合并单元格，但展开后的明细仍须是十列。空白分隔行不属于明细，不写入输出。

每份源文件最末尾的**五个非空行**必须依次是以下汇总，且标签在展开后第六列；`TOTAL FOR CLAIM #` 后允许跟索赔编号。五项任一缺失、顺序错误或不完整，整份文件视为异常，提示“需要手动处理”，不得把汇总当作明细混入结果。

1. `TOTAL QUANTITY`
2. `TOTAL FOR CLAIM #`
3. `TOTAL FREIGHT FEE`
4. `TOTAL HANDLING COST`
5. `TOTAL DISPOSAL FEE`

最终明细是表头与五项汇总之间的全部非空十列行。结构完整但没有明细的文件仍是有效文件，不产生该文件的数据行。单个文件解析错误不阻塞其他文件。

## 4. Invoice number 提取

对每个有效源文件，在**不含 `.xls` 扩展名的文件名**中，从左至右寻找“连续五个 `0`，后面一直到文件名结尾都是数字”的片段。丢弃这五个 `0`，把其后的全部数字原样作为**文本**写到该文件每一条输出明细的第一列。不得把它转成数值，否则前导零会丢失。可用等价于 `0{5}(\d+)$` 的匹配规则。

| 源文件名 | Invoice number | 已提供样例的明细行数 |
|---|---|---:|
| `claim_details_000000400699589.xls` | `0400699589` | 77 |
| `claim_details_000005301102474.xls` | `5301102474` | 1 |
| `claim_details_000005301106261.xls` | `5301106261` | 6 |
| `claim_details_000005301111972.xls` | `5301111972` | 2 |

文件名不符合规则时，只跳过该文件并把文件名和原因写到运行日志。文件夹名称不参与提取。

## 5. 合并与输出数据

Windows 输出真正的 Excel 97–2003 `.xls` 工作簿；macOS 输出真正的 `.xlsx` 工作簿，不能只改扩展名。两者均为单工作表、**11 列**：`Invoice number` 在最左边，后面保留源表十列及顺序。只写一次表头，然后按已排序文件顺序纵向追加明细。输出不得包含源表之间的重复表头、空白分隔行或任意一项底部汇总。`MODEL #` 的可见字样不变；V5 写出的表头在 `MODEL` 与 `#` 之间使用不换行空格 U+00A0。

源值先折叠多余空白。V5 将 CODE、ITEM #、UPC、MODEL #、UNIT COST、CLAIM QTY、CLAIM AMT 的纯数字文本写为数值；无法转为数字的内容保留为文本。DESCRIPTION、ITEM DESCRIPTION、UOM 保留文本。`Invoice number` 无条件保留文本。输出列宽、字体等样式不属于业务验收条件，不能为了样式改变数据。

输出位置是源文件夹；若使用拖入文件方式，则是这组文件共同的父文件夹。文件名为 `合并结果_YYYYMMDD_HHMMSS` 加平台扩展名（Windows 为 `.xls`，macOS 为 `.xlsx`），同一秒重名时依次使用 `_2`、`_3` 等序号。源文件绝不修改或覆盖。工作表名称取第一份有效源文件的文件名主体，移除 Excel 工作表禁用字符并截为最多 31 个字符。

输出总行数（含一行表头）最多 **65,536 行**。若超过上限，不生成输出并在界面报错。应先写同目录临时文件，确认完成后原子替换为正式输出；取消或失败时清理临时文件，不留下半成品。若没有任何有效源文件，不生成结果并提示原因。若一部分文件有效、一部分异常，仍输出有效部分，同时在日志中逐份记录跳过原因。

## 6. V5 界面与交互状态

窗口标题及主标题为“合并文档 V5”，使用项目内橙黄渐变 A 图标。拖拽区主文案为**“拖拽多个.xls文件或文件夹”**；副文案为“或点击此区域选择文件夹”。四个主要按钮分别为“选择文件夹”“开始合并”“取消”“打开输出文件夹”。底部为可滚动、可复制的“运行日志”，旁边有“清空日志”按钮。清空只删除界面日志文字，不删除源文件或输出。

| 状态 | 进度区 | 开始合并 | 取消 | 打开输出文件夹 | 关键行为 |
|---|---|---|---|---|---|
| 初次打开 | 完全隐藏 | 禁用 | 禁用 | 禁用 | 等待选择或拖入 |
| 已扫描且有 N 个候选源文件 | 从中央水平展开，约 0.2 秒后显示完整卡片；显示 `0 / N` | 启用 | 禁用 | 禁用 | 只展示数量，不自动合并；表内校验尚未开始 |
| 未发现源文件或扫描失败 | 隐藏 | 禁用 | 禁用 | 禁用 | 日志写明原因 |
| 正在合并 | 显示已处理数 / N，进度随文件更新 | 禁用 | 启用 | 禁用 | 在后台工作线程处理，界面不冻结 |
| 已完成 | 显示完成状态和最终数量 | 启用 | 禁用 | 启用 | 日志显示合并数、跳过数、明细数及输出路径 |
| 已取消或失败 | 显示对应状态和原因 | 可重新开始 | 禁用 | 禁用 | 不保留不完整输出 |

扫描完成后用户必须**明确点击“开始合并”**才开始校验、读取明细和写文件；拖拽、选择文件夹和展开动画均不是合并入口。处理完成后窗口保持打开，用户可再次选择文件夹或拖入新文件。载入新清单应重置旧输出按钮，避免打开上一次结果。

日志应为每条状态附 `HH:MM:SS` 时间，至少记录载入、扫描数量、开始、每份文件成功或跳过及具体原因、完成摘要、取消或错误、输出路径。无论成功或错误都记录在软件下方日志，不要求另建外部日志文件。处理旧结果时，确认弹窗必须在真正开始合并前出现。

“打开输出文件夹”在完成后打开系统文件管理器，**直接定位并选中刚生成的文件**，而不只是打开一个目录。Windows 使用资源管理器；macOS 使用 Finder。

## 7. 技术架构与平台要求

保持业务引擎和界面分离：文件发现、校验、Invoice number 提取、合并和写出在独立模块；界面只管理选择、状态、后台线程、事件队列和日志。取消使用线程安全标志；工作线程不能直接修改 Tk 控件。所有路径使用 Unicode 安全的路径对象，不把 Windows 分隔符硬编码到业务逻辑。

当前技术基线是 Python 3.11、Tkinter、`tkinterdnd2==0.6.3`、`xlrd==2.0.2`、`xlwt==1.3.0`、`openpyxl==3.1.5`、`pyinstaller==6.22.3`。维护现有项目时，优先在 `app.py` 做平台界面适配，在 `merger.py` 保持 V5 业务规则；保留 `hook-tkinterdnd2.py` 以打包拖拽依赖。A 图标原始 PNG 位于 `assets/a-logo.png`；Windows 图标位于 `assets/app_icon.ico`。这些文件路径是当前仓库的维护指引，产品行为以上文为准。

macOS 版本必须是 Intel `x86_64` `.app`，目标 macOS Big Sur 11.7.9。Mac 窗口图标应使用 PNG 或 macOS 原生图标格式，不能在 Mac 上强行加载 Windows `.ico`。Finder 定位使用与 Windows 不同的系统调用。打包时须包含 Tk、拖拽组件的 macOS Intel 原生库及 A 图标，并对打包后的可执行文件运行 `.xls` 输入、`.xlsx` 输出的自检。`.app` 应通过保留包内符号链接和资源的方式压缩后交付。

**兼容性门槛**：PyInstaller 官方明确指出，在较新 macOS 上打包不能保证能在较旧系统运行；最稳妥的是在要支持的最旧版本上打包。因此，构建机测试通过只说明“候选包已构建并通过自检”，不能写成“已在 Big Sur 验收”。最终至少在上述目标 Mac 上验证启动、拖拽、合并、Finder 定位和重新打开。若没有 Apple Developer ID 签名与公证，交付说明必须提示 macOS 可能要求首次手动允许打开，不得承诺零安全提示安装。

参考：[PyInstaller 跨平台及 macOS 兼容说明](https://pyinstaller.org/en/stable/usage.html)、[Apple Developer ID 与 Gatekeeper](https://developer.apple.com/developer-id/)。

## 8. 独立实现的验收矩阵

1. 用上表四个真实样例作为输入，按文件名排序后，输出恰好 **1 行表头 + 86 行明细 = 87 行、11 列**。Invoice number 四个连续区块依次为 `0400699589`×77、`5301102474`×1、`5301106261`×6、`5301111972`×2；不含任何 `TOTAL` 行。真实业务样例仅用于本地验收，不应上传到公开仓库。
2. 拖入文件夹与拖入同文件夹指定文件是两条独立入口。前者只读取第一层全部合格源文件，后者只读取拖入的文件；两者扫描后均不自动生成输出，开始按钮才是唯一合并入口。
3. 混入旧结果时先提醒；确认后排除旧结果并只合并源文件；拒绝后无新输出。旧结果绝不可重复并入。
4. 错误表头、缺任一底部汇总、错误列数、打不开的文件和不符合五个 `0` 规则的文件分别跳过，界面日志含文件名和可操作的原因；其他有效文件仍可合并。
5. 输出 Invoice number 是文本，包括 `0400699589` 的首位 `0`；其余十列顺序与原明细一致。不同文件的明细行数不同，不得假定每文件固定行数。
6. 65,536 行总量可写；65,537 行不得写。取消或写入失败后，没有损坏的正式结果或残留临时结果；源文件内容及时间戳不变。
7. 初始进度区不占可见区域；读到文件后从中央短暂展开；处理期间可见进度、状态和日志。清空日志不清空选择和已生成文件。
8. Windows EXE 和 macOS `.app` 均能无终端窗口双击启动。Windows 结果仍为 `.xls`，macOS 结果为真正的 `.xlsx`；macOS 最终包须在 Big Sur 11.7.9 Intel 实机验收，完成按钮在系统文件管理器中选中生成文件。

## 9. 给接手开发者的执行顺序

先读本 PRD，再运行现有测试并检查当前代码结构；只做完成验收所需的最小改动。保持 Windows V5 行为不变。新增或更新相关测试，先验证原失败，再验证修改后通过。对打包产物运行真实或合成的 `.xls` 自检；将 Mac 构建机测试与 Big Sur 实机测试结果分别记录。最后提交 Git 版本。任何未在目标 Mac 验证的产物都必须标注“候选包”，不能宣称“可直接安装且兼容”。
